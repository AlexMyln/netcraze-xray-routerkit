# Публикация без конфиденциальных данных

Храните учётные данные, dotenv-файлы, SSH-ключи, связки сертификатов и ключей,
подписки, сгенерированные конфигурации Xray и резервные копии роутера вне Git.
`.gitignore` закрывает эти типы файлов, но не защищает уже отслеживаемые файлы
или принудительное добавление через `git add -f`. Не используйте реальные
значения в примерах, тестах, сообщениях коммитов и именах файлов.

Перед коммитами настройте свой подтверждённый GitHub noreply:

```sh
git config --local user.email 'YOUR_GITHUB_NOREPLY_ADDRESS'
git config --local user.useConfigOnly true
```

Возьмите точный адрес из GitHub **Settings → Emails**. Включите приватность email
и блокировку командных push, раскрывающих личный адрес. Используйте noreply для
автора, коммитера, строк соавторства и аннотированных тегов. Адрес владельца
репозитория нельзя использовать для выдачи другого участника за владельца.

После добавления изменений в индекс выполните:

```sh
python3 scripts/check_public_data.py
python3 -m unittest tests.test_check_public_data -v
```

Локальная проверка охватывает все достижимые коммиты и теги, пути во всех
исторических деревьях, файловые объекты, сообщения коммитов и тегов, email,
индекс и отслеживаемые рабочие файлы. Неполная shallow-история, недоступные
объекты, подмодули, слишком большие файлы, приватные имена файлов и архивы
блокируются. Проверяются и распространённые сигнатуры архивов с изменённым
расширением, бинарные объекты и UTF-16. Игнорируемые неотслеживаемые приватные
входные данные намеренно не входят в набор для публикации.

Правила обнаруживают приватные ключи, распространённые токены провайдеров,
значения авторизации, JWT, VLESS-профили, параметры Reality, UUID, длинные
значения учётных данных и email вне доменов примеров. Каталоги тестов и примеров
не исключены. В полях автора, коммитера и создателя тега допустим только GitHub
noreply. Диагностика содержит ID объекта, правило и номер строки, без найденных
значений и имён файлов. Изучайте объект локально; не переносите исходное
содержимое в публичные issues или логи CI. Поиск по шаблонам — дополнительный
барьер, а не доказательство отсутствия любых приватных или закодированных данных.

CI получает полную историю веток и тегов, запускает проверку до остальных шагов,
использует права только на чтение и не сохраняет учётные данные checkout.
Регрессионные тесты проверки запускаются на Python 3.8 и текущем Python.
Оставляйте включёнными независимые механизмы GitHub secret scanning и push protection.

## Очистка email в истории 2026-10-17

Личный email заменяется подтверждённым noreply владельца в полях автора,
коммитера и строках соавторства во всех публичных ветках и тегах. Содержимое
исторических деревьев файлов, имена авторов, даты и структура слияний сохранены.
ID изменённых коммитов и потомков меняются; прежние подписи коммитов теряют силу.
Названия релизных тегов и содержимое файлов сохраняются. Исторические ID базовых
версий в документах приёмки остаются записью исходных проверок, а не новой
приёмкой оборудования.

[Карта релизных тегов](history-email-rewrite-tags.json) содержит исходный и новый
ID коммита и неизменный ID дерева файлов для каждого тега. В замороженном контракте
canary alpha.16 исходный ID базы остаётся идентификатором evidence; при получении
исходников сверяйте текущий релизный тег с этой картой.

После переписывания используйте свежий клон. Не сливайте и не отправляйте старые
ветки и теги: так можно вернуть историю с личным email. Резервный bundle должен
оставаться приватным и находиться вне репозитория. Форки, локальные клоны,
служебные ссылки pull request и кэшированные страницы GitHub могут сохранять
исходные объекты; переписывание веток и тегов их не удаляет. Эти места проверяются
отдельно; при необходимости используется процедура обращения в поддержку GitHub.
