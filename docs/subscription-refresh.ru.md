# Автоматическое обновление подписки

RouterKit умеет получать свежую HTTPS-подписку **каждые 2 часа на самом
роутере**. Это подхватывает изменения серверного порта, адреса и параметров
VLESS Reality, пока провайдер сохраняет точные уникальные имена выбранных узлов.
Ноутбук, RMM и запущенный AI-агент для фоновой работы не нужны.

Обычный `setup` сохраняет выбранные узлы в статические профили. Обновление
подписки включается отдельно командами ниже; обновление исходников RouterKit
само по себе не включает расписание на существующих установках.

## Включение на установленном RouterKit

Команды выполняются **в Linux/Entware shell целевого aarch64/arm64 роутера
от root**, после обычного bootstrap/install. `/opt` должен оставаться отдельным
EXT4 mount на предназначенном для Entware внешнем накопителе. На рабочей станции
mutable команды запрещены. Один только RMM с native CLI/RCI без Entware shell
не может установить этот обработчик.

1. Убедиться, что имеется пакет Entware `cron`, `/opt/bin/python3`,
   `/opt/bin/curl` и рабочий `S23xray-direct`. Если `cron` отсутствует,
   установить его через проверенный `/opt`-scoped `opkg` в рамках разрешённой
   установки. RouterKit не скачивает пакеты при периодическом обновлении.
   Используется [Entware Vixie cron с поддержкой cron.d](https://github.com/Entware/rtndev/blob/master/cron/Makefile).
2. Из checkout RouterKit передать URL подписки через скрытый ввод:

   ```sh
   python3 scripts/routerkit.py subscription configure --yes
   ```

   Альтернатива — существующий owner-only файл с URL (0600, текущий владелец,
   без symlink/hardlink) или выделенная переменная `ROUTERKIT_*`:

   ```sh
   python3 scripts/routerkit.py subscription configure --source-file /private/source.secret --yes
   python3 scripts/routerkit.py subscription configure --source-env ROUTERKIT_SUBSCRIPTION_SOURCE --yes
   ```

   Не передавать URL значением аргумента командной строки, не вставлять его в
   чат и не публиковать файл. Переменная удаляется из окружения рабочего
   процесса после чтения. Для фоновых запусков источник сохраняется отдельно.

3. Включить расписание:

   ```sh
   python3 scripts/routerkit.py subscription enable --yes
   python3 scripts/routerkit.py subscription status
   ```

   `enable` сначала выполняет одно немедленное обновление с проверкой. Затем
   копирует самодостаточный обработчик в `/opt/lib/routerkit/subscription/`,
   проверяет его запуск, устанавливает только собственный файл
   `/opt/etc/cron.d/routerkit-subscription` и запускает/проверяет Entware cron.
   Checkout после этого не нужен для расписания. После обновления исходников
   повторный `enable --yes` обновляет установленную копию обработчика.

Расписание `0 */2 * * *` запускает проверку в 00 минут каждого чётного часа
по времени роутера. Entware `S10cron` должен быть разрешён для запуска при
загрузке. Проверка восстановления после реальной перезагрузки — отдельное
аппаратное доказательство, локальные тесты его не заменяют.

## Применение и восстановление

- Сначала RouterKit связывает уже установленные профили с узлами подписки,
  сравнивая сгенерированные VLESS outbounds. При первом связывании допустима
  разница только в серверном порту: механизм можно включить и после его смены.
  При несовпадении UUID/host/Reality-параметров выбор автоматически не угадывается.
  Для явно выбранной миграции можно передать `configure --selection-file PATH`:
  owner-only `04_outbounds.json`, ранее созданный штатным генератором RouterKit
  для нужных узлов. Набор profile tags должен точно совпадать с установленным;
  каждый выбранный outbound должен полностью совпасть с единственным узлом
  актуальной подписки, включая порт. Порядковые номера и приблизительное
  сходство не используются. Этот файл задаёт только привязку узлов; inbounds,
  routing и native policies из него не импортируются.
- Далее используется точное исходное имя узла, независимо от порядка узлов
  в подписке. Изменение UUID, адреса, порта или ключей у того же имени может
  обновляться автоматически. Переименование, удаление или неоднозначное имя
  останавливает весь текущий цикл, сохраняя установленный конфиг; требуется
  повторное явное связывание. Новые узлы и профили сами не добавляются.
- Источник хранится в `/opt/etc/routerkit/subscription/source.json` (0600,
  каталог 0700). Сохраняется исходный HTTPS URL: HTTP redirects не заменяют
  его временным конечным адресом. Используется существующий resolver с TLS,
  SSRF/destination policy, ограничениями времени, размера и числа redirects.
  Принимаются raw/Base64/JSON VLESS Reality TCP подписки существующего parser.
  Для HTML landing page сначала нужен настоящий subscription URL из
  разрешённого защищённого subscription flow. Статическая VLESS-ссылка не
  может служить источником автоматического обновления.
- Если серверные параметры не изменились, проверяется работа профилей,
  конфигурация не переписывается и Xray не перезапускается.
- При изменении создаётся приватная staging-копия всех JSON fragments и
  выполняется `xray run -test`. После проверки изменяется атомарно **только
  `04_outbounds.json`**. Локальные SOCKS-порты, inbounds, split-routing/direct
  overrides, native Proxy/Policy и назначения клиентов сохраняются.
- Xray перезапускается через существующий `S23xray-direct`. Проверяются
  PID/исполняемый файл, владение loopback-сокетами и HTTPS через каждый
  SOCKS-профиль с remote DNS и проверкой TLS. Ошибка применения возвращает
  предыдущий локальный конфиг и перезапускает Xray. Возврат старого конфига
  не обещает доступность старого upstream, если провайдер уже сменил порт.
- Журнал `/opt/var/lib/routerkit/subscription/pending.json` содержит одну
  предыдущую версию и сохраняется до успешной проверки. При прерывании питания
  следующий запуск сначала восстанавливает локальное состояние по журналу.
  При постороннем изменении outbound-файла восстановление останавливается,
  не затирая неизвестную конфигурацию. Постоянно растущий архив не создаётся.
- Параллельные циклы исключены kernel lock. После завершения/аварии процесса
  блокировка освобождается автоматически. Сеть, пустая/неподдерживаемая
  подписка и TLS-ошибки не заменяют текущий конфиг. Следующая плановая попытка
  выполняется через 2 часа; можно запустить её вручную раньше.

## Ручной запуск, статус и отключение

После установки обработчика, без checkout:

```sh
/opt/bin/python3 /opt/lib/routerkit/subscription/routerkit-subscription.py run
/opt/bin/python3 /opt/lib/routerkit/subscription/routerkit-subscription.py status
/opt/bin/python3 /opt/lib/routerkit/subscription/routerkit-subscription.py disable --yes
```

`status` возвращает только состояние настройки/расписания, наличие процесса
cron, интервал, Unix timestamps последней попытки/успеха и результат
`updated`/`unchanged`/`failed`. URL, исходные имена узлов, UUID и ключи не
выводятся. `enabled` означает наличие точного задания; отдельно проверяется
`scheduler_running`. Статус не заменяет фактическую проверку VPN-клиента.

Отключение удаляет только собственное cron-задание. Текущая конфигурация
Xray, защищённый источник и остальные задания сохраняются. Установка/обновление
Xray, reboot, firmware, native policies, DNS и firewall в этот механизм не входят.
